# Approved delivery goal

Build and publish AwesomeAwesomeness through Agentflow's end-to-end SDLC. The application and the linked delivery story are equally required outcomes. User activation: 2026-09-02, explicit approval to execute with durable checkpoints, early deployment, recovery test, and no heartbeat.

## Product contract

- Discover source candidates through GitHub repository search (Awesome names/descriptions/topics); verify they are resource lists.
- Include only public source repositories observed at >=50,000 stars. Store observation time, query, revision, attribution and inclusion/exclusion decisions.
- Extract linked resources locally, normalize safely and deduplicate while preserving every source relationship.
- Never recursively ingest a linked list unless it independently qualifies.
- Hosted app reads committed catalogue snapshots. No runtime GitHub token, crawling, remote model call or dependence on the local computer.
- Search, topic/source filtering, sorting, pagination, shareable searches, source pages, freshness and a delivery-story view.
- Editorial visual design; responsive layout, useful empty states, keyboard access and readable contrast.
- No accounts, payments, user data persistence, paid infrastructure or mandatory AI enrichment.

## Acceptance matrix

- DATA: All published sources meet the observed-star threshold; every resource has source provenance; exclusions and limitations disclosed.
- APP: Search/filter/pagination/navigation and empty states pass automated tests and real browser checks.
- UX: Chief-designer/UX perspectives review rendered desktop and mobile screens; blocking findings resolved.
- LOCAL: Crawler/enrichment only local; refresh resumes safely and preserves last good published snapshot.
- SDLC: Applicable phases, role passes, handovers, issue-scoped commits, PRs, versions and releases verifiable in GitHub.
- COUNCIL: Architecture, UX and release councils have actual participant/context attribution, bounded questions, common evidence and objection dispositions.
- HARNESS: Capability resolution, honest fallback, bounded helpers/loops, provenance, stale-evidence rejection and recovery demonstrated. Distinguish stable native contracts from project-level tests.
- RECOVERY: Resume from durable evidence without duplicate external operations or a second writer.
- STORY: An illustrated story links decisions, checks, releases and the live app.
- PUBLIC: App works independently of the local computer; running code/data versions match the verified release.

## Authority and constraints

The user authorized in-scope setup, installation, commits, pushes, PRs, merges, releases and free Streamlit publication. All project-controlled local files remain inside this repository. No heartbeat, global installation, permission weakening or secrets in evidence. This approval does not override platform enforcement or a genuinely required human gate.

Stakeholder reviews are explicitly agent-simulated. Same-platform helpers do not prove cross-platform role alternation. Standard-profile self-review remains disclosed. Councils advise the accountable role; unresolved blocking objections prevent acceptance.
